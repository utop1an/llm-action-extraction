# cEASDRL / RISeC 完整复核说明

复核日期：2026-11-18。结论：**现有模型确实完成了 RISeC 训练；96.75% 动作 F1 和 81.82% 关联参数 F1 在冻结的原转换口径下可以复算。但它是 cEASDRL 的适配版，不是原论文结果的严格复现；原报告存在标注范围和实验流程表述不够准确的问题。**

本次没有重新训练、改动原始数据、改动冻结训练目标或调整预测。新增了独立核验脚本，修正了结果汇总与说明，并计算了标注范围敏感性。下述检查通过，不等于逐条人工确认 RISeC 标注均正确。

## 1. 实际任务和输出

输入是一整篇操作文本；输出每个动作的完整文本名称、它对应的完整参数名称，以及两者在原文中的位置。名称直接按预测位置从文本截取，不从金标准补全。

例如，测试集真实预测中有 `Place(the roast, the marinade)`、`pour(the marinade, a saucepan)`、`Thread(the roast, a rotating barbecue spit, indirect heat)`。输出也保留错误，例如 `boil(boil)`，没有人工修正。

本实验中的“参数”是与动作关联的文本片段，范围含食材、工具、时间、温度、其他修饰语和目的从句。它不是 PDDL 中的有类型变量，也不输出前置条件、效果或可执行的 PDDL domain。

不预测 ES/EX/OP，也不要求预测关系角色。隐含内容的恢复、条件从句，以及目标为另一个动作的关系均不在当前训练/主评估范围内。原始文本没有明说的对象，不会由这个抽取任务自动补出。

## 3. 两个模型是什么，怎样训练

“动作模型”和“参数模型”是串联的两个抽取网络，均为 CNN/DQN。它们不是两个 PDDL action model。

1. 动作抽取网络读全文，为 token 依次做 O/B/I 决策，组成完整动作名称。
2. 参数抽取网络读某个动作周围的文本及到该动作的距离，依次做 O/B/I 决策，组成该动作的参数名称。
3. 测试主流程只用第一个网络预测的动作建立第二阶段输入。第二阶段不会获得正确动作列表、参数标签或标注边界。

O 表示不抽取，B 表示一个片段开始，I 表示片段延续。因此 `a rotating barbecue spit` 可以作为一个完整参数，邻接的两个参数也不会因为都是正标签而被合并。

词表示使用冻结的 GloVe-100 与 ELMo-small-768；CNN/DQN 权重在 RISeC train 上重新初始化并训练。不是微调大语言模型。训练时金标准 BIO 标签用于奖励；通过经验回放和 DQN Bellman 目标更新 Q 网络。推理时不使用金标准。

| 设置 | 当前选中实验 |
|---|---|
| seed | 0，单种子 |
| 训练轮数 | 两个阶段各完成 10 轮 |
| 优化器 | Adam，学习率 0.001 |
| gamma | 0.9 |
| 探索率 | 首轮由 1 降至 0.1 |
| 并行训练环境 / 回放 batch | 16 / 32 |
| 更新频率 | 每 4 个向量步骤优化一次；每 100 次优化同步 target |
| 回放容量 | 每个阶段最多 50,000 条 |
| 回放采样 | 名义正奖励比例 0.9，实际 batch32 中为 28 条，即 87.5%；正奖励部分平衡正确 O/B/I |
| rate shaping | 按解码后的片段起点数计数，避免把一个多词名称算成多个抽取 |
| action 最佳 checkpoint | 第 8 轮，dev F1 95.88% |
| argument 最佳 checkpoint | 第 10 轮，dev F1 80.67%（给定正确动作） |

动作阶段共 152,850 个 token 决策、5,600 次优化；参数阶段共 1,391,140 个 token 决策、23,250 次优化。权重有更新，训练损失与梯度有限，保存/加载输出一致。

检查点选择依据 dev 完整片段 F1。动作阶段曾有三个完成的候选，选 dev 最优者；参数阶段使用平衡回放候选中的 dev 最优轮次。参数训练和参数 dev 选模使用标注动作，这是训练设置；主测试用预测动作，二者没有混为一个指标。

**流程限制：**训练脚本在每个候选完成后自动计算 test 分数，再进行跨候选选择。选模函数只读 dev，未发现它使用 test F1 的代码路径，但不能据此声称“测试集全程封存、所有方案冻结后才首次访问”。正式对比实验应把测试评估移到所有模型与配置冻结之后。

## 4. 与原版 cEASDRL 的关系

保留了上下文词表示、两个 CNN/DQN 抽取阶段、状态标签、参数距离输入、Bellman 目标和经验回放框架。另用原 Keras CNN 加载训练后的参数，对齐前向 Q 值；最大绝对差为动作 0.00030518、参数 0.00012207，均通过既定数值检查。

但当前有明确修改：PyTorch/GPU 向量化实现；二元 select/reject 改为 BIO 三类；动作容量从 500 改为 600；引入 BIO 类别平衡回放和按片段计数的 shaping；target 网络独立于 online 网络；不做 ES/EX/OP；数据和评估均换为 RISeC 的完整片段关联任务。选中版本的代码哈希与训练记录一致。

前向数值对齐证明复用了相应 CNN 计算，不证明整个训练轨迹、任务设置或论文成绩已经复现。因此准确名称是 **“cEASDRL-based BIO adaptation trained on RISeC”**。本项目未在原论文的旧数据集上重现其指标，也没有在本轮新增 NL2P/LLM 对比结果。

## 5. F1 如何计算

这里是完整 mention 的 micro F1，不是逐 token F1，也不是词表中不同名称的去重命中率。

- 动作正确：文档、出现位置、完整名称均匹配。大小写和空白规范化；不做同义词或词形归并。
- 参数正确：正确的动作实例与完整参数实例组成的链接匹配。名称对了但挂错动作，算错。
- 漏掉动作时，它的所有金标准参数链接仍计入漏检。预测了错误动作时，其参数预测也会进入错误计数。

`Precision = TP / (TP + FP)`；`Recall = TP / (TP + FN)`；`F1 = 2TP / (2TP + FP + FN)`。

| 冻结原口径，78 篇 test | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| 完整动作名称 | 862 | 40 | 18 | 95.57% | 97.95% | **96.75%** |
| 完整参数名称及其动作关联 | 1,447 | 474 | 169 | 75.33% | 89.54% | **81.82%** |

参数预测共 1,921 条，金标准 1,616 条。**81.82% 是预测动作条件下的端到端分数。**给定正确动作时，参数阶段 test F1 是 83.57%，仅作诊断，不能替代主结果。

旧的 88.85% / 26.44% 来自首词目标适配版，并已按同一个完整名称计分器重算。它训练过 RISeC，但完整名称目标处理不合适，旧参数训练仅 3 轮。与当前 10 轮 BIO 平衡回放实验相比，数据目标、奖励、采样和预算同时变化；不能把提升归因于单个修复，也不能当作同预算消融实验。

新输入只有文字时可以输出预测；要计算 F1，还需要这段文字的人工动作、参数及归属标注。

## 6. 本次发现的具体问题

### 6.1 TODO 关系被纳入无角色参数目标

转换器把动作指向非动作、非条件从句且不带 `_X` 的关系纳入目标，没有限定关系必须是论文定义的 `Arg*`。因此包含 45 条 `TODO`。`TODO` 不在论文给出的关系类型表中。

这不证明这些边全部错误：例如 `brown -> oil`、`remove -> a slotted spoon` 看起来可以是合法的无角色参数关系。但它们的角色未定，未经逐条判定，不能把目标集描述为“仅由明确类型关系组成”或“已清洗完标注”。本次保留原训练产物，另外报告以下敏感性。

| 参考标注范围（模型和预测固定） | 正确链接 | 预测链接 | 金标准链接 | 参数 F1 |
|---|---:|---:|---:|---:|
| 冻结原口径，含 TODO | 1,447 | 1,921 | 1,616 | 81.82% |
| 仅保留已定义 Arg*、仍排除条件从句 | 1,441 | 1,921 | 1,606 | 81.71% |
| 已定义 Arg*，再把条件从句纳入参考 | 1,441 | 1,921 | 1,740 | 78.72% |

测试中 10 条 TODO 有 6 条被模型命中。排除它们时预测不删除，6 条相应预测变成 FP，所以分数略降。**后两行只更换参考口径，没有在相应口径下重训，不能报告为清理后重训成绩。**条件从句本来未被训练成目标，第三行只说明任务范围会影响分数。

### 6.2 “1,695 条隐含参数”的名称不准确

旧字段 `implicit_arguments` 是混合排除集合。实际由 1,528 条带 `_X`/`_Z` 标记的关系、111 条 `Next`/`Simultaneous` 动作时序关系、56 条其他动作目标关系组成。56 条中还有 19 条 TODO。不能全部称为隐含参数。它们原先已排除在主评估外，修正统计名称不会改变已发布 F1。

### 6.3 模型仍有明显错误

测试有 474 个参数 FP、169 个参数 FN；其中有 33 个预测把动作自身的原文片段当成参数。在当前目标排除动作目标的定义下，这些是错误。参数 precision 只有 75.33%，不能把 81.82% F1 解读为已可靠解决参数抽取。

这次没有根据 test 错误添加过滤规则后重报成绩，避免把测试集变成开发集。下一轮改模型应在 train/dev 上决定规则或架构，再使用冻结评估协议。

## 7. 实际完成的验证及证据边界

- 523 个源文件哈希与内容、260 篇 canonical 文本及 token/字符映射通过检查。
- 所有原始 AC 和纳入目标的参数位置逐项比对；所有训练/评估示例与目标 manifest 一致。
- 三个 split 的文档 ID/规范化全文无交集；相似度筛查另有记录。
- 1,430 个训练/开发/测试特征缓存和 360 个预测动作上下文缓存通过哈希、维度和有限值检查；表示被冻结。
- 两个 last checkpoint 中保留的各 50,000 条回放记录逐条检查，共 100,000 条；索引均指向 train，标签、状态转移、终止标记和奖励符合定义。它们是保留的回放缓冲区，不是全部历史转移。
- 原始 BRAT 字符位置独立计分，没有调用原项目计分函数，TP/预测数/金标准数及 P/R/F1 与报告一致。
- 全部 78 篇 test 去掉标注字段重新推理；batch 从 32 改为 7，全部预测逐项一致。缓存仅提供相同文本的冻结词表示。
- 28 项相关测试重新通过。训练源码、checkpoint 与原记录的哈希吻合；没有改动被冻结的训练实现。

上述证据未发现 split、训练样本索引或推理金标签泄漏，不能证明所有标注语义正确、食谱间完全无相似性、预训练数据无重叠或单种子结果稳定。单种子且只有料理域；跨领域泛化和统计稳定性尚未得到验证。

## 8. 当前可以怎样使用这些结果

可作为**固定 RISeC 转换口径下、已复核的 cEASDRL 适配版初步结果**。正式论文对比应先固定 TODO 与条件从句处理口径、保留源标注和更改清单，再统一所有方法的 train/dev/test 与完整链接计分；测试评估推迟到选择冻结之后，增加多个训练种子。若要称严格原版复现，还需要另做忠于原版的实现/原数据验证。

原结果没有被本次否定，但需要上述限定。不能写成“严格复现 cEASDRL 后，在无标注问题的新 planning benchmark 上得到 81.82%”。
